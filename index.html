// 01 — KERNEL

NOT A CHATBOT.
NOT SAAS. AN OPERATING SYSTEM.

Chatbots answer questions. SaaS rents you a dashboard in someone else's cloud. Babuba is the system layer your company runs on — installed on your hardware, booting agents that do real work.

01/KERNEL

THE GATEWAY

One process. One port. One router that reads every message and decides which agent handles it — and which workflow to start.

02/PROCESSES

ONE AGENT PER DEPARTMENT

Finance, ops, MIS, admin. Each agent is a process with its own memory, tools, guardrails and approval rules — isolated, auditable, replaceable.

03/SHELL

YOUR CHANNELS

Talk to it where you already work — WhatsApp, Telegram, Gmail, web chat. The shell you already have, connected to the OS underneath.

// 07 — MAN BABUBA

QUESTIONS, ANSWERED.

$ man babuba --data+

Does my data leave my server?

No. The gateway, agents and database run on your machine. Your data never goes to our cloud — you can even run it fully air-gapped.

$ man babuba --model+

Which LLM does it use?

Bring your own — OpenAI, Anthropic, DeepSeek, Ollama, or any OpenAI-compatible endpoint. No lock-in; swap models per agent.

$ man babuba --install+

How long does deployment take?

About fifteen minutes on a standard server or desktop. One install command, then connect your channels and boot agents.

$ man babuba --agents+

Can agents really approve things?

They prepare, verify and flag. Humans approve — every action requiring approval lands on your phone with the full picture. One tap to approve, one tap to reject.

$ man babuba --limit+

What if an agent does something wrong?

Guardrails, role-based access and approval gates contain it. Every action is logged and searchable — roll back, fix the rule, move on.

$ man babuba --why+

Why an OS and not an app?

Because agents aren't a feature — they become the way your company works. That needs a system layer: one router, many processes, shared memory, full audit. That's what an OS is.
