DEFENSE IN DEPTH.

Not a chatbot with a password. A system with layers — identity, scope, rules, gates and logs.

5 LEVELS
Super admin → viewer. Custom roles with per-resource permissions. Scoped per department and per agent.
GUARDRAILS
4 MODES
Allow, deny, warn, require-approval — per topic, per agent, enforced before and after every model call.
APPROVAL GATES
100%
Payments, exports, sends — nothing ships silently. Every gated action waits for a human tap.
AUDIT
FULL
Who, what, when, which rule allowed it — logged, searchable, exportable. Roll back, fix the rule, move on.
APPROVAL.GATE

NOTHING SHIPS SILENTLY

Agent prepares and verifies. The action lands on your phone with the full picture — one tap to approve, one tap to reject. Approval gates on payments, exports, sends.

AUDIT.LOG

EVERY ACTION, RECORDED

Every agent action is logged and searchable — who, what, when, which rule allowed it. Export the log any time. Roll back, fix the rule, move on.

SECRETS

KEYS STAY LOCAL

Model API keys, tokens and secrets live in your gateway's secret store — never in our cloud, never in logs. Per-agent scoping included.

access — example

[ask] $ babuba access --check asha finance.approve

[rbac] asha = viewer (level 1) → DENIED

[guardrail] payment action = require-approval pass → gate

[gate] escalates to finance admin (level 4) → notified

[audit] denied access logged · searchable
